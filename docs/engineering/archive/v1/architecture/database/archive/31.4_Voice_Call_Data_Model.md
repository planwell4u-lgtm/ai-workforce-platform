# 31.4 Voice Call Data Model

**Version:** 1.0  
**Phase:** 31 – Database Architecture  
**Status:** Draft  
**Owner:** Platform Architecture Team

---

# 1. Purpose

This document defines the Voice Call Data Model for the AI Voice Agent SaaS Platform.

It provides the logical architecture for managing the complete lifecycle of voice calls, including:

- Inbound PSTN calls
- Outbound calls
- SIP sessions
- LiveKit rooms
- AI conversations
- Human transfers
- Call recordings
- Speech transcripts
- Timeline events
- Billing usage

---

# 2. Goals

The voice data model must support:

- High-volume concurrent calls
- AI-first call handling
- Human takeover
- Call recording
- Full conversation history
- Analytics
- Billing
- Compliance
- Multi-tenancy

---

# 3. Supported Call Types

- Inbound
- Outbound
- Callback
- Warm Transfer
- Cold Transfer
- Internal
- Conference
- Test Calls

---

# 4. Core Entities

The voice domain consists of:

- Phone Number
- Call
- Call Leg
- SIP Session
- LiveKit Room
- Recording
- Transcript
- Timeline Event
- Call Metrics

# 7. Call Entity

Represents the primary voice interaction.

Typical attributes:

- Call ID
- Tenant ID
- Twilio Call SID
- Direction
- Status
- Caller
- Callee
- Agent ID
- Conversation ID
- Started At
- Ended At
- Duration
- Cost
- Recording Status

---

# 8. Call Legs

A single call may contain multiple legs.

Examples:

- Customer → AI
- AI → Human Agent
- Human Agent → Supervisor

Each leg maintains:

- Start time
- End time
- Status
- Participant
- SIP details

---

# 9. SIP Session

Stores SIP metadata:

- Call-ID
- From
- To
- User-Agent
- Codec
- Transport
- RTP Information

Supports:

- Twilio SIP
- SIP Trunks
- Enterprise PBX

---

# 10. LiveKit Room

Maps the voice call to a LiveKit room.

Stores:

- Room Name
- Room SID
- Participants
- Join Time
- Leave Time

---

# 11. Recording

Multiple recordings may exist for a single call.

Examples:

- Full call
- Customer only
- AI only
- Human transfer segment

Metadata:

- Storage URL
- Duration
- Codec
- Size
- Retention Date

---

# 12. Transcript

Stores speech-to-text output.

Each segment includes:

- Speaker
- Timestamp
- Text
- Confidence
- Language

Supports:

- Partial transcripts
- Final transcripts
- AI summaries

---

# 13. Timeline Events

Every state transition is recorded.

Examples:

- Call Created
- Ringing
- Answered
- AI Joined
- Tool Invoked
- Transfer Requested
- Transfer Completed
- Recording Started
- Recording Stopped
- Call Ended

---

# 14. Integrations

Supported providers:

- Twilio
- LiveKit
- OpenAI
- Deepgram
- ElevenLabs
- Cartesia

---

# 15. Multi-Tenancy

Every voice entity contains:

- tenant_id

Tenant isolation is enforced through PostgreSQL Row Level Security.

---

# 16. Security

- Encrypted recordings
- Secure transcript storage
- RLS
- Audit logging
- Configurable retention policies

---

# 17. Performance

Recommended strategies:

- Monthly partitioning for Calls
- Monthly partitioning for Timeline Events
- Index tenant_id
- Index call_sid
- Index conversation_id
- Index started_at

---

# 18. Analytics

The data model supports:

- Average call duration
- AI containment rate
- Transfer rate
- Answer time
- Queue time
- Recording duration
- Cost per call

---

# 19. Retention

Suggested defaults:

| Data | Retention |
|------|-----------|
| Calls | Permanent |
| Timeline | 2 Years |
| Recordings | Configurable |
| Transcripts | Configurable |
| Metrics | Permanent |

# 21. Design Principles

- Voice-first architecture
- Event-driven lifecycle
- Multi-tenant by design
- Immutable timeline
- AI and human collaboration
- High-performance indexing
- Compliance-ready

---

# 22. Summary

The Voice Call Data Model provides the foundation for all voice communications within the platform. It supports complete call lifecycle management, integrates with Twilio and LiveKit, enables AI and human collaboration, and supplies the data required for analytics, billing, auditing, and compliance.
