# 31.3 User & RBAC Model

**Version:** 1.0

## Purpose

Defines the identity, authentication, authorization and Role-Based
Access Control (RBAC) model for the platform.

## Goals

-   Secure authentication
-   Fine-grained authorization
-   Multi-tenant user isolation
-   Least privilege
-   Enterprise-ready permissions

## Core Entities

-   Tenant
-   User
-   Role
-   Permission
-   UserRole
-   API Key
-   Service Account

## Relationship

``` text
Tenant
 ├── Users
 ├── Roles
 └── API Keys

User
 ├── User Roles
 └── Permissions (via Role)
```

## Authentication

-   JWT Access Tokens
-   Refresh Tokens
-   OAuth/OIDC ready
-   MFA support
-   API Keys

## Authorization

Permissions are granted through roles.

Example:

``` text
Admin
 ├── manage_users
 ├── manage_agents
 ├── manage_billing

Supervisor
 ├── view_calls
 ├── manage_campaigns

Agent
 ├── answer_calls
 └── view_assigned_conversations
```

## Recommended Roles

-   Platform Admin
-   Tenant Owner
-   Tenant Admin
-   Supervisor
-   AI Designer
-   Billing Manager
-   Support Agent
-   Read Only

## Security

-   Password hashing
-   Account lockout
-   Audit logging
-   Session management
-   Row Level Security

## Audit

Log:

-   Login
-   Logout
-   Password reset
-   Permission changes
-   Role assignment
-   API key creation

## Design Principles

-   Least privilege
-   Default deny
-   Tenant isolation
-   Immutable audit trail

## Summary

This document defines the RBAC foundation used by all platform services.
